Proof for every code change

Spyglass is a CLI for coding agents and the people who review their work. It verifies code changes with real tools and keeps the evidence.

Start the quickstart View the source

A statement is not proof

An agent says the tests pass and the page works . Spyglass keeps the step, the evidence and every failed attempt.

One run, start to finish

  1. First, start a run on the source you have.

    spyglass up --run terminal-trial --plan verification-plan.json
    {
  "id": "terminal-trial",
  "state": "ready",
  "source": {
    "commit": "8e85659b7715d6de5a321b527c7e3a3fbcd4804d",
    "hash": "c6328e4926046754f26a07c59d588f1bfec278491eb974f637f47bf912819b09"
  },
  "pendingClaims": ["health-ready"],
  "result": ".spyglass/runs/terminal-trial/spyglass/result.json",
  "next": "spyglass result --file .spyglass/runs/terminal-trial/spyglass/result.json --run terminal-trial"
}

  2. Then drive real tools. A failed attempt stays in the record. 

    spyglass check deliberate-failure --run terminal-trial
spyglass check health --run terminal-trial
spyglass status --run terminal-trial
    CHECK_FAILED: Check deliberate-failure failed: one or more assertions failed; the structured result reports failure.
Next: Inspect the retained attempt and artifacts, correct the cause, then rerun the check.

"completedChecks": [
  { "name": "deliberate-failure", "step": "8cbb29c2-d61", "status": "failed" },
  { "name": "health", "step": "b97266d0-842", "status": "passed" }
]

  3. Finally, record the result, clean up and write the report. 

    spyglass result --run terminal-trial --file .spyglass/runs/terminal-trial/spyglass/result.json
spyglass down --run terminal-trial
spyglass report --run terminal-trial

Six real surfaces

Repository checks

Run the checks you already have. A check that exits zero but reports a failed assertion still fails. 

$ spyglass check deliberate-failure
"exitCode": 0,
"claims": [{
  "id": "health-ready",
  "ok": false,
  "detail": "Deliberate fixture failure"
}],
"overall": false,
"passed": false

Web browser

An isolated browser opens only the origins in your profile. Each proof keeps a screenshot, the page tree, errors and requests. 

$ spyglass ui snapshot
- heading "Sign in" [level=1, ref=e1]
- textbox "Email " [required, ref=e3]
- textbox "Password " [required, ref=e4]
- button "Sign in" [ref=e2]

HTTP

Send a real request and state the status you expect. Redirects are not followed, and credentials are masked. 

$ spyglass api GET /health --expect 200
API_EXPECTATION_FAILED: API returned HTTP 401; expected 200.
"status": 401,
"body": { "error": "sign in required" },
"path": "8a427527-232-1-api-response.json"

PostgreSQL

One statement in a read-only transaction, with a row bound. A statement that starts as a write is not sent at all. 

$ spyglass db 'SELECT 42::int AS answer' --expect-rows 1
"rows": [{ "answer": 42 }],
"rowCount": 1,

$ spyglass db 'CREATE TABLE spyglass_write_guard(id integer)'
DATABASE_READ_ONLY: Spyglass accepts read-only SQL only.
Next: Use SELECT, WITH, VALUES, TABLE, SHOW or EXPLAIN. The query was not sent.

Docker Compose

Read the status of the project's own containers, then read the logs from a named mark in the run. 

$ spyglass ps
"service": "db",
"state": "running",
"health": "healthy",
"missing": [],

$ spyglass logs db --since before-check
"mark": "before-check",
"markedAt": "2026-10-22T20:02:58.207Z"

Any other command

Wrap a command to keep its real exit status and bounded output as an artifact with a checksum. 

$ spyglass exec -- git log --oneline -1
"exitCode": 0,
"stdout": "08524b2 base\n",
"artifacts": [{
  "path": "ee12d4e9-782-1-git-output.txt",
  "sha256": "0087caed43039ac921cdd657e058b669bc42fe6e4c9e9a9d32ae81c032136ed6"
}]

Failures it refuses to pass

Failure cases that the Spyglass CLI must detect, from docs/failure-cases.md, with the code it reports.
Area Failure What Spyglass does Code
Source Source changes after the run starts. Later evidence cannot prove a claim about the original source. STALE_SOURCE
Check A check exits zero but reports a failed assertion. The check fails and keeps the result, assertions and artifacts. CHECK_FAILED
Claim A required claim has no completed step. The claim cannot pass. The report stays incomplete. CLAIM_INCOMPLETE
Claim A side effect has no independent read after it completes. The claim cannot pass. An HTTP 202 is not a read. INDEPENDENT_READ_MISSING
Browser An action targets an origin outside the allowlist. The action fails and names the policy. BROWSER_ORIGIN_BLOCKED
Browser A screenshot exists but nobody inspected it. The visual claim stays incomplete. VISUAL_INSPECTION_MISSING
HTTP A request returns an unexpected status. The expected-status check fails and keeps the response. API_EXPECTATION_FAILED
Database A query tries to write data. A write statement is not sent. The read-only transaction blocks the rest. DATABASE_READ_ONLY
Database A query returns a different row count than expected. The command fails and keeps the observed count. DATABASE_ROW_COUNT
Run Two operators change one run at once. One command owns the lock. The other fails with a recovery step. RUN_BUSY
Report Cleanup did not happen. The report is written, but the run is incomplete. CLEANUP_PENDING
